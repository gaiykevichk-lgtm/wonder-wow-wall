> **Статус:** Черновик

> **Дата:** 2026-07-15

---

## 1. Общее описание

### Назначение
Wizard для создания/редактирования **вариантов базовых панелей** — комбинаций размера панели, текстуры (материала), цвета и фотографий.

### Контекст
В системе уже есть:
- **Panel** — базовая панель (размер 30×30, 30×60, 60×60, цена)
- **Texture** — текстура/материал (бетон, дерево, мрамор...)
- **TextureColor** — цвет текстуры (#808080, #FFFFFF...)
- **VariantImage** — комбинация (design_id, texture_id, color_id) → фото

### Новая сущность: PanelVariant
Связь **базовой панели** с **текстурой**, **цветом** и **фотографиями**:
```
Panel (базовая панель)
  └── PanelVariant
        ├── texture_id: FK → Texture
        ├── color_id: FK → TextureColor
        └── images: string[] (пути к S3)
```

## 3. Модель данных (Backend)

### Таблица: `panel_variants`
```sql
CREATE TABLE panel_variants (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    panel_id        UUID NOT NULL REFERENCES panels(id),
    texture_id      UUID NOT NULL REFERENCES textures(id),
    color_id        UUID REFERENCES texture_colors(id),  -- nullable для кастомных
    color_hex       VARCHAR(7),  -- для кастомных цветов (#RRGGBB)
    image_paths     TEXT[],      -- массив путей S3 (первый = главное фото)
    is_active       BOOLEAN DEFAULT TRUE,
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW(),
    
    -- Уникальность: один цвет на комбинацию panel+texture
    UNIQUE(panel_id, texture_id, color_id)
);

CREATE INDEX idx_panel_variants_panel ON panel_variants(panel_id);
CREATE INDEX idx_panel_variants_texture ON panel_variants(texture_id);
```

### API Endpoints

#### POST /api/admin/panel-variants/batch
Создание нескольких вариантов за раз (после wizard).
```json
// Request
{
  "panel_id": "uuid",
  "variants": [
    {
      "texture_id": "uuid",
      "color_id": "uuid",       // null если кастомный цвет
      "color_hex": null,        // null если есть color_id
      "image_paths": ["s3://...", "s3://..."]
    }
  ]
}

// Response 201
{
  "created": 5,
  "variants": [...]
}
```

#### GET /api/admin/panel-variants?panel_id=xxx
Список вариантов для панели.

#### PATCH /api/admin/panel-variants/{id}
Обновление варианта (добавление/удаление фото, смена цвета).

#### DELETE /api/admin/panel-variants/{id}
Удаление варианта.

#### DELETE /api/admin/panel-variants/{id}/images
Удаление конкретного фото из image_paths.

## 4. Хранение файлов

### S3 Integration
- **Bucket:** `wonder-wow-wall-panels` (отдельный от основного)
- **Path pattern:** `panels/{panel_id}/{variant_id}/{filename}`
- **Formats:** JPG, PNG, WEBP
- **Max size:** 10 MB per file
- **Presigned URLs** для загрузки и просмотра

### Upload Flow
1. Frontend запрашивает presigned URL: `POST /api/admin/media/presign`
2. Backend возвращает URL для загрузки напрямую в S3
3. Frontend загружает файл напрямую в S3
4. Frontend отправляет final path в API

## 5. UI/UX

### Navigation
- Wizard в модальном окне или на отдельной странице
- Progress bar показывает текущий шаг
- Кнопки "Назад" / "Далее"
- Валидация перед переходом на следующий шаг

### Responsive
- Desktop: карточки в 3-4 колонки
- Tablet: 2 колонки
- Mobile: 1 колонка, стековый wizard

### Empty States
- Шаг 2: "Нет доступных текстур" — ссылка на создание в AdminTexturesPage
- Шаг 3: "Загрузите хотя бы одно фото"

### Error Handling
- Ошибка загрузки в S3 → toast + retry
- Slug конфликт → inline error в форме
- Validation errors → подсветка полей
