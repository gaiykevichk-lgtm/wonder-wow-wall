# Фото в дизайне варианта панели

## Назначение

Для каждой строки `panel_variant` (конкретная панель + фактура) хранится отдельный массив `design_image_paths`. Он независим от `image_paths`:

- `image_paths` — фотографии исполнений/фактур;
- `design_image_paths` — пользовательские интерьерные фотографии панели с выбранной фактурой.

Галерея карточки товара сначала показывает выбранное исполнение, затем — только `design_image_paths` выбранного варианта. Fallback на другие исполнения или общие визуализации не используется.

## Реализация

- PostgreSQL: `panel_variants.design_image_paths JSON NOT NULL DEFAULT []`, миграция `020` после `019`.
- Domain/application/SQL repository сохраняют оба массива независимо.
- Public/admin API всегда возвращают `design_image_paths`; admin PATCH принимает его для добавления и удаления.
- В `Каталог → Варианты панелей` есть отдельные колонки «Фото исполнений» и «Фото в дизайне».
- В редакторе варианта есть отдельный блок загрузки, просмотра и удаления интерьерных фото.
- При загрузке object key строится с `panel_id` и текущим выбранным `texture_id`.
- ID варианта показывается полностью, в компактной колонке 170 px с переносом и кнопкой копирования; обрезка через `...` удалена.

### Ограничение проверки

Защищённый `/admin/catalog` нельзя визуально открыть в headless Preview без админской сессии, а авторизованный cloud browser владельца недоступен этому агенту. Поэтому внешний сценарий реальной загрузки через production-аккаунт не подтверждён кликом; его frontend-часть подтверждена компонентным тестом (File → presigned upload с panel/texture → PATCH `design_image_paths`), а backend/schema — реальными production-проверками.
