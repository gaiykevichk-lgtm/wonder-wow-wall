# Карточки объектов и исполнения на странице «Пространства»

Дата: 22.10.2026

## Цель
Одна карточка соответствует одному объекту внутри адреса. Фотографии и материалы объекта собраны внутри этой карточки; фото/материал выбирает только явно связанное исполнение. Если связь не задана, исполнение автоматически не подставляется, а при создании карточки его нужно выбрать.

## Реализация
- Сохранены проектная связь, адрес и связь с исполнением в моделях и ответе публичного каталога.
- Витрина группирует варианты строго по `project_id`, не по совпадающему названию/адресу.
- Админская форма позволяет задать проект, адрес и связанное исполнение; обязательные поля проверяются и на клиенте, и в backend.
- Детальная карточка связывает выбор изображения с явно указанным исполнением; список исполнений показывает миниатюру и название.
- Backend и frontend тесты обновлены.

## Стек и локальная проверка
React 19 + TypeScript + Vite 8; backend FastAPI + SQLAlchemy + PostgreSQL.
- Frontend: `npm run build`, `npx tsc --noEmit`, целевой Vitest для группировки `spaceProjects`.
- Backend regression tests находятся в `backend/tests/api/admin/test_texture_combination_gallery.py` и `backend/tests/application/test_texture_combination_image_update.py`.
- Локальный backend требует зависимостей проекта; в системном окружении отсутствует FastAPI.

## Статус
Frontend build, TypeScript и целевые 3 теста grouping проходят. Backend regression тесты не удалось собрать локально (FastAPI отсутствует); на установленном production backend нет pytest. Preview HTTP для `/spaces` отвечает 200, но screenshot сервиса отображает страницу ошибки доступности dev-сервера, поэтому визуальный preview не подтверждён. Production страницы `/spaces` по HTTPS отвечает 200, однако изменения этого комплекта туда не выкладывались: production backend/API и frontend bundle развернуты раздельно, а безопасная проверка связей карточек и назначений на production перед выкладкой не выполнена.
