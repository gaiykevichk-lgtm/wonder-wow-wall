# Выбор текстуры после создания базовой панели — 26.09.2026

Сценарий: «Каталог» → «Варианты панелей» → строка новой базовой формы без текстуры → выбор в существующем выпадающем списке. Создание базовой формы не меняется.

Причина ошибки `Catalog row not found`: опубликованный backend проверял существование каталожного назначения даже при `current_texture_id=""`, когда строка ещё виртуальная и такого назначения нет. В исходниках проекта обработчик для пустого значения уже был, но на опубликованном backend он отсутствовал.

Изменение на сервере: в `panel_variants.py` перенесена только ветка для пустого `current_texture_id`: под блокировкой панели создаётся/активируется каталожное назначение выбранной текстуры. Базовая панель и её форма создания не изменены. Исходный файл сервера сохранён в `/opt/app/deploy-backups/texture-empty-row-20260926/panel_variants.py`.

Проверено: локальный backend-тест пустой строки (вместе с двумя соседними проверками) — 3 passed; компонентный тест выбора текстуры — 1 passed; frontend build успешен. После перезапуска backend импортирован запущенный обработчик с новой веткой, сервер запустился, неавторизованный запрос к API отвечает 401. Авторизованный выбор на конкретной пользовательской строке и повторное чтение назначения через UI пока не воспроизведены; не считать скриншот или HTTP 200 подтверждением этого сценария.

## Сохранение позиции при выборе текстуры (26.09.2026)

Причина перемещения: прежний обработчик записывал первое назначение с максимальным `sort_order + 1`, а пустая виртуальная строка отображалась сверху. После refetch она оказывалась внизу. Теперь первое назначение получает `sort_order=-1`, а клиент объединяет виртуальные и впервые сохранённые строки по дате создания панели (с сохранением соседства копии и оригинала). Порядок обычных существующих строк с неотрицательным `sort_order` не меняется; форма создания панели не затронута. Исправления источников перенесены на опубликованный сервер после резервной копии в `/opt/app/deploy-backups/texture-order-20260926/`. Пересборка опубликованного frontend прошла, backend перезапущен. Локально пройдены 3 backend-теста, 3 выборочных frontend-теста на позицию и выбор фактуры, frontend build. Авторизованный end-to-end сценарий на опубликованной странице не проверен: гостевая страница админки не предоставляет доступ к таблице.

## Ошибка `Variant group not found` при повторной смене текстуры

Опубликованный обработчик смены текстуры всё ещё отклонял строку без вариантов исполнения (`if not rows: 404`), хотя каталог хранит назначение отдельно от исполнений. Локальный исходник уже допускал пустую группу. На VM удалена только эта проверка внутри `PATCH /panel-variant-rows/texture`; остальное поведение, включая запрет текстуры-дубликата и сохранение `sort_order`, не менялось. Резервная копия серверного файла: `/opt/app/deploy-backups/empty-texture-20260926/panel_variants.py`.

Проверено после перезапуска: тесты backend — 3 passed; вызов именно работающего обработчика на реальной пустой каталожной строке с другой текстурой успешно меняет назначение, возвращает пустой список исполнений и сохраняет порядок. Проверка выполнена в транзакции с откатом, неизменность назначения после отката подтверждена. Выборочные frontend-тесты пустой строки и позиции — 2 passed. Авторизованный UI-сценарий на опубликованной странице агентом не выполнен.
