# ID в таблице «Варианты панелей»

Проблема: в колонке ID показывался `panel_variants.id`, а в строке без загруженного исполнения — строковый `assignment:<id>`. После фильтра «Базовая форма» запрос вариантов ограничивался одним выбранным panel ID, хотя фильтр объединяет несколько panel по общему slug. Поэтому та же каталожная строка могла превратиться в placeholder и показывать иной ID.

Решение: колонка ID показывает и копирует только `panels.id` (`record.panel_id`), независимо от наличия исполнений. На общем экране список исполнений загружается без ограничения representative panel ID, а фильтрация формы выполняется по slug для всех строк; в контексте конкретной панели (`panel` prop) запрос остаётся ограниченным её ID. Технический rowKey/идентификаторы исполнений для операций редактирования не меняются. Данные каталога и миграции не затрагиваются.

## Каталог: единая карточка семейства форм

По требованию пользовательского каталога одноимённые/однослуговые базовые формы одинаковой геометрии должны отображаться одной карточкой, как «КОЛОННА», с совокупностью связанных фактур и исполнений. `groupVariantsToPanels` агрегирует панели по slug без суффикса размера и точным `width_mm × height_mm`; карточка представляет первую запись семейства, а варианты собираются по всем panel_id семейства. Страница товара загружает активные исполнения и фильтрует их по тому же семейству. При покупке и переходе в конфигуратор сохраняется `panel_id` выбранного исполнения — исходные записи/связи БД не перепривязываются.

Проверки: TypeScript, выборочные компонентные тесты отображения ID с фильтром, порядка строк и размера, сборка frontend. Для продакшена применяется точечный патч активного JS-чанка после сверки входных фрагментов и резервной копии. Авторизованная проверка UI остаётся отдельной стадией.
