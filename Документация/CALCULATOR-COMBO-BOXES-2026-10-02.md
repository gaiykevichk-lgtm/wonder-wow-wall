# Калькулятор «Рассчитать проект»: комбо-режим по коробкам — 2026-10-02

## ТЗ
Комбинированный дизайн: две текстуры на одну стену. У каждой позиции —
свой типоразмер, исполнение и количество коробок. Продажа только коробками
(поштучно нельзя), стоимости позиций суммируются. Моно-режим не трогаем
(уже работает адекватно).

## Backend (`backend/app/infrastructure/api/calculate.py`)
- `CombinedItemRequest`: поле `boxes: int | None` (1..10_000) рядом с `share`.
- `_calc_one(..., boxes)`: режим «по коробкам» — без `ceil`, `actual_area = boxes × box_area_m2`.
- Комбо-ветка: если хоть у одного item есть `boxes` — строгое суммирование
  по коробкам, у каждого breakdown-элемента `share`/`wall_area` пересчитаны
  из фактических метражей; иначе — прежний режим нормализованных долей.
- Контракт: `POST /api/calculate`
  `{height, width, panel_size, design_type:"combined", design_id, items:[{panel_size, boxes}]}`,
  ответ — прежняя форма `CalculationResult` + `breakdown[]`, итоги — простые суммы.
- Тесты `backend/tests/api/test_calculate.py`:
  `test_combined_boxes_mode_sums_boxes_without_rounding`,
  `test_combined_boxes_endpoint`. **19/19 passed.**

## Frontend (`CalculatorSidebar.tsx` + контекст страниц)

  типоразмер (3 кнопки в ряд), поле «Количество, коробок» (`кор.` addon,
  подпись «= N панелей · продажа только коробками»).
- Позиция 1 — текстура/исполнение из карточки товара.
- Позиция 2 — `Select` «Вторая текстура» + `Select` «Вариант исполнения»
  (появляется после выбора текстуры; при смене текстуры чужое исполнение
  сбрасывается). Справочник — `context.textures`.
- `calculatePrice` в комбо шлёт `items:[{panel_size, boxes}]` (долей нет).
- Шаг 3: расшифровка «Позиция N · типоразмер · текстура — X кор. · Y шт.».
- `CatalogPanelPage.tsx` / `ProductPage.tsx` передают в контекст
