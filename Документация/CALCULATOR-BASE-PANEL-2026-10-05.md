# Комбинированный дизайн: выбор базовой панели

Запрос: во второй позиции выбирать базовую панель, её текстуру и исполнение.

Изменены CalculatorSidebar.tsx, CatalogPanelPage.tsx и CalculatorSidebar.test.tsx. Контекст карточки передаёт все панели и связанные варианты из существующих публичных запросов. Смена панели сбрасывает текстуру/исполнение, список текстур ограничен панелью; поле исполнения видно постоянно и блокируется до выбора текстуры. Callback передаёт две позиции; карточка валидирует принадлежность вариантов и создаёт отдельные строки корзины.

Проверки: 34 профильных теста прошли, в том числе выбор другой панели и фильтрация её текстур. Полный typecheck tsconfig.app завершился heap OOM с лимитом 512 MiB; успех typecheck не подтверждён. HTTP карточки в dev 200, screenshot показал только loader: визуальный flow не подтверждён. Production не изменён.

Осталось: проверить полную цепочку выбора, корзину с реальным API и цены по идентификаторам вариантов (текущий calculate API учитывает размеры/коробки, но не идентификаторы второй панели/исполнения), затем изолированная публикация. Не считать завершённым.

## Production 2026-10-05
Изолированная правка фактических production CompanionsCarousel и CatalogPanelPage, без полной локальной сборки. Калькулятор загружает действующий публичный список панелей и вариантов при открытии, группирует текстуры по выбранной базовой панели; сбрасывает дочерние поля при смене, блокирует покупку неполной позиции. Передаёт реальные варианты в callback; карточка добавляет две строки с отдельными variantId/panelId. Моно-ветка сохранена. JS graph перевыпущен с suffix combopanel (102 модуля), node --check прошёл для каждого. Бэкап /opt/app/deploy-backups/combo-base-panel-20261005. Публичный bundle содержит новые поля; оба справочника HTTP 200. Screenshot карточки — skeleton: модалка и добавление в корзину на production end-to-end не подтверждены. Backend calculate не менялся, сохраняется ограничение расчёта цены по размерам/коробкам, а не по variantId.
