# Создание размерных панелей

Задача: при создании формы выбрать только существующие размеры (30×30, 30×60, 60×60 см), сохранив каждый как самостоятельную панель со своим ID. Реализация сохраняет текущий React/Vite frontend и FastAPI/PostgreSQL backend без миграции данных.

- Вкладка «Базовые формы» и редактор из «Варианты панелей» используют одну форму `AdminUploadPage`. В режиме создания отмечаются размеры; фото и цена после создания редактируются индивидуально у каждой панели. Цена первоначально берётся из существующих `BASE_PANEL_PRICES` (890/1490/2490 ₽).
- `POST /api/admin/panels/sizes` принимает имя, базовый slug, список размеров, описание и активность. Суффикс размера добавляется к slug, например `krug-300x300`. Запрос предварительно проверяет конфликты; существующие панели с совпадающими именем, размером и slug возвращаются без перезаписи данных. SQL-репозитории разделяют одну транзакцию запроса. Старый `POST /api/admin/panels` оставлен для совместимости.
- Для новой размерной панели отдельный ID; текстуры, исполнения и фотографии существующих панелей не копируются и не изменяются. Кнопка «Подключить размер» у панели с размерным суффиксом помогает заполнить базовые сведения и добавить ещё один размер.
- Редактирование ранее созданной панели остаётся индивидуальным. Старые записи без суффикса не группируются автоматически: автоматическое сопоставление по названию могло бы объединить разные формы. Их ID и связи сохранены.

Проверка: frontend `npm run build`, `npx vitest run src/domains/admin/__tests__/AdminUploadPage.test.tsx`; backend `python3 -m pytest tests/api/admin/test_panels.py -q`. Локальный frontend запускается из `frontend` через `npm run dev -- --host 0.0.0.0 --port <port>`. API требует авторизации администратора. Секреты в документации не хранятся. Публикация отдельно не выполнялась.
