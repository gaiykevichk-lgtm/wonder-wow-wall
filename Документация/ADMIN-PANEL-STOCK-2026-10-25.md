# Учёт остатков SKU панелей

## Требование
Остаток уменьшается только при оформлении/подтверждении покупки покупателем в корзине. Смена статуса заказа администратором не влияет на остаток. Администратор не может менять остатки вручную.

## Реализация
- Остаток хранится на панели-SKU в `panels.stock_quantity`.
- `POST /api/orders` агрегирует quantity по panel SKU заказа, проверяет активность вариантов/панелей и доступное количество, блокирует строки SKU через `SELECT ... FOR UPDATE`, уменьшает остаток и создаёт заказ в одной транзакции.
- Для memory repository используется process-local asyncio lock.
- Админский PATCH больше не принимает `stock_quantity`; колонка и inline-редактирование остатков удалены из UI админки.
- Админский переход статуса заказа не списывает товар.

## Проверки
Добавлены сценарии успешного списания при оформлении, недостаточного количества и параллельного оформления в памяти; API-тест проверяет списание и отказ от повторной покупки при нулевом остатке.

## Ограничения/статус
Нужны запуск релевантных backend/frontend тестов, production-сборка и выкладка с backup и end-to-end проверкой. Не выкладывать, пока проверки не завершены.
