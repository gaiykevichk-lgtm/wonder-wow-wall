# Выдача фотографий «Пространств» — 2026-10-08

Симптом: пользовательский скриншот админ-каталога tab=texture-images показывает битые обложки и миниатюры.

Диагностика: файлы существуют, шесть опубликованных обложек декодируются Pillow как PNG 2048×1364/1365. Ответ nginx передавал Content-Encoding: aws-chunked из S3 при обычном PNG-теле. Это некорректные метаданные представления; связь с конкретным пользовательским сбоем окончательно не подтверждена браузерной консолью (личный браузер offline).

Production-правка только nginx: /etc/nginx/conf.d/upload-encoding.conf содержит map, убирающий исключительно aws-chunked и сохраняющий прочие кодирования. В двух существующих S3 locations /etc/nginx/sites-enabled/wonder-wow-wall скрыт исходный Content-Encoding и добавлен нормализованный. Файлы изображений, БД, frontend, видео не менялись.

Backup: /opt/app/deploy-backups/upload-encoding-20261008/nginx.before.conf. nginx -t успешен, nginx reload выполнен.

Проверки после правки: все 31 уникальный URL галерей (SELECT только чтение) возвращают HTTP 200 image/png без aws-chunked. Реальный серверный браузер открыл изображение РЕЙКА; скриншот просмотрен — интерьер и деревянные рейки видны. /spaces рендерится, но скриншот через 8 секунд показывает пустые области карточек; это не подтверждает восстановление списка изображений. Проверка авторизованной админ-таблицы блокирована offline личного браузера. Статус частичный: исправлена некорректная HTTP-выдача, точный пользовательский сценарий пока не подтвержден.
