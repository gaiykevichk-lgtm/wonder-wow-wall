# Как пользоваться режимами «Чат», «План», «Агент»

Дата: 28.09.2026. Область: общение о проекте Wonder Wow Wall в Promto. Это памятка по работе, а не утверждение, что интерфейс уже автоматически проводит задачи через CI/CD.

## Три режима, видимые пользователю

| Режим | Для чего | Ожидаемый результат | Что **не** следует из выбора режима |
|---|---|---|---|
| **Чат** | Вопросы, исследование, оценка, чтение и объяснение | Ответ с источником фактов и пределами уверенности | Ни файлов, ни коммита, ни релиза просто из-за обсуждения |
| **План** | Сформулировать исполнимое ТЗ до разработки | `.md` с целью, границами, критериями приёмки, проверками и рисками; на экране написано «План и .md. Без запуска» | Само наличие плана не означает, что код написан, тесты прошли или прод обновлён. Коммит плана — желаемая дисциплина, но не подтверждённая кнопкой гарантия |
| **Агент** | Выполнять явно поставленную задачу: менять код, запускать, проверять и при запросе публиковать | Артефакт, проверки и точный отчёт о результате/блокере | «Код, запуск, публикация» означает возможности режима, а не обязательный деплой при любом сообщении; вопрос, аудит или документация не дают согласия менять прод |

Режим может переключаться вручную; автоматическое переключение возможно только если оно действительно реализовано в интерфейсе и явно показано пользователю. По одному скриншоту наличие такого автомата не подтверждено.

## Как поставить задачу без двусмысленности

- «Разберись, ничего не меняй» → **Чат**: ответ с фактами, без изменения проекта.
- «Составь план по задаче X» → **План**: самостоятельное ТЗ в `.md`; оно должно быть пригодно для передачи в исполнение без потери требований. Если нужен Git-коммит самого плана — уточнить это отдельно или зафиксировать как командное правило.
- «Реализуй X локально, проверь, коммить, но не выкладывай» → **Агент**: локальная работа, целевые тесты и коммит **только относящихся к задаче** файлов, без деплоя.
- «Реализуй X и выкати на прод» → **Агент**: до выкладки проверить готовность и зависимости, сохранить возможность отката, выполнить релиз и проверить публичный пользовательский сценарий. Если релиз небезопасен или недоступен — не выдавать его за успешный.
- «Что из этого на проде?» → **Чат** для аудита, независимо от статуса Git: сравнить текущую публичную выдачу, конфигурацию/артефакты и при возможности проверить сценарий.

## Git и прод — две разные оси

```text
Локально: файл изменён → git add (staged) → git commit (история)
Прод: сборка/миграции/ресурсы → выкладка → проверка публичного сценария
```

Оси пересекаются, но не равны друг другу. Файл можно вручную выложить без коммита; коммит можно оставить без релиза. ` M` — изменённый отслеживаемый файл не подготовлен к коммиту; ` D` — удалённый отслеживаемый файл не подготовлен; `??` — новый, пока не отслеживаемый файл (не «неизвестное состояние»). `M ` / `A ` — подготовлено к коммиту. **Ни один из этих символов не означает «на проде».**

Пользователю полезно видеть три **итога выполнения**, не путать их с техническими шагами:

1. **Исследовано / спланировано** — ничего не внедрено.
2. **Реализовано локально** — код/тесты и, если уместно, коммит; прод не подтверждён.
3. **Опубликовано и проверено** — публичная версия содержит изменение и проверен требуемый сценарий.

Между ними допустимы промежуточные сообщения «релиз выполнен, но проверка не завершена» или «заблокировано». Их **нельзя** обозначать как третий, успешный итог. Для задачи без продукта (например, памятки или отчёта) третья ступень не нужна.

## Что должен сообщить агент в конце

- Что конкретно изменил; какие файлы затронул; что осталось вне объёма.
- Уровень проверки: сохранение файлов, тесты/сборка, локальный интерфейс, серверная доставка, публичный сценарий — только фактически проверенный уровень.
- Git-коммит (если был) и публикация (если была) — отдельно; по возможности версия или проверяемый идентификатор релиза.
- Если что-то не удалось, конкретный блокер и безопасный следующий шаг без заявления «всё готово».

**Главное правило:** опубликованным для клиента считается не `git commit`, не HTTP 200 и не скопированный файл, а подтверждённая работа нужного изменения в публичном пользовательском сценарии.
