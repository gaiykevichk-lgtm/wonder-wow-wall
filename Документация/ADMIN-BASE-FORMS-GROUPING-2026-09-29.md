# Группировка базовых форм по размерным SKU

Запрос: во вкладке «Базовые формы» одна форма (например, ПИРАМИДА) должна отображаться одной строкой, независимо от количества размеров и повторных записей. При выборе размера сохраняется конкретный ID панели для дальнейших операций. Размеры 30×30 и 300×300 должны отображаться единообразно.

Решение: административный список загружает все страницы отфильтрованных панелей и группирует записи по нормализованному названию (регистр/пробелы); пагинация выполняется уже по формам. В строке размер выбирается по ID панели. Фото, slug, цена, статус, дата, редактирование и удаление относятся к выбранной панели. Если у одной формы есть несколько записей одинакового размера, выпадающий список дополнительно показывает их полные ID. Данные и связи заказов не удаляются и не меняются. Из миллиметров `width_mm`/`height_mm` формируется единый формат `30×30 см`, независимо от старой текстовой метки.

Ограничение: группировка по названию применяется только в отображении вкладки; это не миграция БД и не отдельная сущность базовой формы. В других частях каталога панели остаются отдельными SKU. Два разных типа с одним названием будут выглядеть одной формой в этой вкладке; для полноценной независимой идентичности типа понадобится отдельный `form_id` в модели.

Проверка: компонентный сценарий выбора второго размера проверяет ID в payload PATCH; отдельно проверено отображение устаревшей метки в мм. Пройдены 17 тестов страницы, TypeScript и цельная сборка Vite.
