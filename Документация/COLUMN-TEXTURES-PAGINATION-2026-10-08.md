# Материалы КОЛОННЫ: обрезанный публичный список исполнений

Сценарий: /catalog/bbe26910-6690-4f72-8878-3a8d02b6bb88 не отображает материалы, хотя админка содержит 39 исполнений в 8 фактурах.
Evidence: GET /api/panel-variants возвращал первые 100 записей без КОЛОННЫ, но запрос panel_id возвращал 39. Публичный use case использовал list_all(offset=0,limit=100), а endpoint отдаёт массив без пагинационных параметров. Поэтому frontend фильтровал неполные данные.
Решение: ListPanelVariantsPublic загружает все страницы репозитория до применения существующих фильтров публикации и фактуры. Запрос по panel_id не изменён. Данные/назначения/изображения не менялись.
Перед выкатом файл prod сравнен с локальным через cmp (совпадение). Только этот файл опубликован; backup /opt/app/deploy-backups/column-textures/panel_variant_use_cases.py. Backend container перезапущен.
Тесты: регрессия 139 записей с КОЛОННОЙ после первых 100 и исключением выключенного назначения + существующие design-image tests: 3 passed. После restart public API отдаёт 157 записей, КОЛОННА 39, 8 групп: Графика, Декоративные фактуры, Дерево, Кожа, Краска, Металл, Природный камень, Текстиль.
