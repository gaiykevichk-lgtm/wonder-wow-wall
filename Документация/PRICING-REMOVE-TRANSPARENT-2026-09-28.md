# Удаление блока «Прозрачное ценообразование»

Задача: полностью убрать названный блок со страницы `/pricing`, сохранив hero, преимущества, цитату, баннер активной подписки и выбор плана.

Локальная реализация: из `frontend/src/domains/subscription/ui/PricingPage.tsx` удалены секция с тремя карточками базовых панелей, её расчёт цен и неиспользуемый запрос настроек магазина. Видеофон hero и карточки планов не менялись. В `PricingPage.test.tsx` добавлена проверка отсутствия блока при сохранении списка планов.

Проверка 2026-09-28: два теста PricingPage и TypeScript прошли, локальная сборка прошла. Локальный screenshot `/pricing` показал только загрузчик — визуально отсутствие блока на нём не подтверждено.

Production: исходник `/opt/app/frontend/src/domains/subscription/ui/PricingPage.tsx` изменён с резервной копией `/opt/app/deploy-backups/pricing-section-before-20260928T144240Z/PricingPage.tsx`. Сборка на сервере завершилась успешно, но серверный `index.html` использует иной входной граф, а новый `dist` всё ещё содержал старую секцию. Поэтому дополнительно точечно удалена секция в отдаваемом чанке `PricingPage-BiqV1hKt-C2__UQ4a.js`; исходный чанк сохранён в той же backup-папке. `node --check` успешен; публично отдаваемый чанк содержит планы и не содержит название или карточки удалённой секции. Публичный screenshot успел показать только часть страницы до полной анимации/загрузки; это не подтверждает весь flow визуально.

Попытка сменить URL чанка и входного JS привела к белому экрану на публичном screenshot. Входной JS и HTML немедленно восстановлены из резервной копии, после отката публичный screenshot снова показывает обычную страницу. Новый чанк сохранён, но не используется. Текущий публичный HTML ссылается на прежний входной JS и прежнее имя чанка `PricingPage-BiqV1hKt-C2__UQ4a.js`, содержимое которого на origin обновлено. Из-за неизменного имени и immutable-кэширования прежняя версия блока может оставаться у посетителей; отсутствие блока в пользовательском браузере не подтверждено. Нужен аккуратный релиз с новым URL чанка и целостным entry graph после диагностики причины белого экрана. При повторной сборке серверный устаревший исходный граф может вернуть блок.
